# First week

1. Run `python research.py doctor` and `python research.py demo`. The demo is synthetic and tests the workflow, not your paper's findings.
2. Create a paper with `new`. Fill `research/question.md` with the economic object and competing explanations. Use `idea-and-literature` before committing to a method.
3. Map existing data and old analyses using `data/README.md`, `state.json`, and `artifacts.json`. Do not move a working legacy paper automatically. For adoption, use `docs/legacy-adoption.md`.
4. Write a model protocol and an economic-test protocol separately. Specify what could falsify the idea; freeze primary comparisons before a large search. Exploration remains welcome and labeled.
5. Ask for code first if the method is unsettled. Ask for a learning memo before expensive training you cannot yet explain.
6. Run a tiny synthetic or permitted subsample check, then the authorized full analysis. Store complete estimates; diagnose surprises before interpreting them economically.
7. Write the test descriptions yourself. Ask the agent for separate grammar and logic review; integrate only the requested edits.

For a new chat: “Read AGENTS.md and run context for PAPER. Tell me the current question, authoritative artifacts, unresolved choices and next authorized task.” Git does not contain your old chats; durable notes must be written into the paper workspace.
