# Research Teaching

Choose depth from the request: quick conclusion; research discussion; full learning guide; or mentor explanation. Define the economic object before architecture or software terms. For a guide, explain prerequisites, objective/equations with subscripts, algorithm/training, worked synthetic example, code mapping, baseline and failure modes. Relate to verified source versions and the actual implementation. Separate assumptions, demonstrated results and unresolved issues. the researcher should be able to defend why a method addresses the question; “this model had the best result” is not an explanation. Use English by default and Chinese when requested.

Read [the relevant protocol](../../../docs/prompts.md) when carrying out this workflow. Read `profiles/researcher.md` and the active paper context for preferences; current user instructions prevail.
